# Evaluation corpus and question set

## Provenance disclosure — read this before trusting any number derived from this data

Both `corpus/` (10 documents) and `questions.json` (40 questions) in this
directory were **authored by Claude (Anthropic), the AI assistant used to
build this project, at the user's request** during Phase 7. They have
**not** been independently reviewed, fact-checked, or validated by a human
domain expert.

This matters because it's exactly the failure mode the project's evaluation
spec explicitly warns against: *"Do not generate questions with an LLM and
treat them as ground truth without saying so."* This document is that
disclosure. Any recall@k, MRR, or groundedness number computed against this
question set should be read as **"how this system performs against a small,
AI-authored test set,"** not as an independently validated benchmark.

What was done to keep this honest anyway:

- The corpus's factual documents (geography, solar system, Python history,
  WWII dates, Mount Everest, human body systems, coffee brewing,
  renewable energy) use widely-known, easily independently-verifiable
  facts — not obscure or contestable claims — specifically so a human
  reviewer could fact-check them quickly.
- Two documents (`company_quarterly_report.docx`, `board_game_collection.pdf`)
  use explicitly synthetic/fictional data (a made-up company, a made-up
  personal game log) and say so in their own text, so there's no
  real-world-accuracy question to even ask about them.
- Questions are tied to specific `expected_documents` by filename, so
  retrieval grading is checkable by opening the corpus file directly.
- 10 of the 40 questions are deliberately unanswerable from this corpus
  (`"category": "unanswerable"`, `"expected_documents": []`) to test
  whether the system correctly declines rather than fabricating an answer
  — this is graded on the answering/groundedness path, not recall@k.

If you (the user) want this to become a real benchmark, the next step is
for a human to read `corpus/` and `questions.json` end to end and either
approve, edit, or replace them. Nothing downstream in this project (Phase
9's benchmark report) should describe results from this set as more
authoritative than what's disclosed here.

## Corpus

10 short documents, one per topic, spanning all four supported formats
(plain text, HTML, DOCX, PDF) and exercising the structural features this
project's extraction/chunking care about (headings, tables with captions,
a two-column PDF layout):

| File | Format | Structural features |
|---|---|---|
| `geography_capitals.txt` | plain text | none (baseline) |
| `renewable_energy_overview.txt` | plain text | none (baseline) |
| `solar_system.html` | HTML | headings, table with `<caption>` |
| `python_history.html` | HTML | headings |
| `world_war_2_timeline.html` | HTML | headings, table with `<caption>` |
| `company_quarterly_report.docx` | DOCX | headings, table, caption paragraph |
| `human_body_systems.docx` | DOCX | headings |
| `mount_everest.pdf` | PDF | two-column layout |
| `coffee_brewing_guide.pdf` | PDF | headings |
| `board_game_collection.pdf` | PDF | ruled table |

Generated by `scripts/generate_eval_corpus.py` for the DOCX/PDF files
(reproducible); the `.txt`/`.html` files are committed directly.

## Questions

`questions.json`: 40 questions, 3 per real document (30 total, mixing
direct factual lookup, table lookup, and paraphrased/no-literal-overlap
phrasing to exercise the dense-vs-lexical contrast) plus 10 questions
answerable by none of the corpus documents.
